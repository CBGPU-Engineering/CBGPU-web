# AdFit: desktop and mobile revenue operations

This is a measurement and deployment guide, not evidence of increased revenue.
No production advertisement requests were generated by the test suite.

## Registered units

| Environment | Actual supplied unit | Dimensions |
| --- | --- | --- |
| Desktop web | `DAN-kVpBmlPRbOvGb6oi` | 728 × 90 |
| Mobile web | `DAN-vpZNfcj3tj0jMkhV` | 320 × 50 |

There is no supplied 320 × 100 unit. Create that size in the AdFit console
before testing it; changing the dimensions of the existing unit is not valid.
Verify every serving hostname is registered and approved in the actual account.
The source allowlist is a safety boundary, not proof of console approval.

The slot chooses a supplied unit using the available container width. Narrow
containers use mobile dimensions, including narrow desktop windows. It never
scales an advertisement or causes horizontal scrolling. Resizing does not
trigger a new advertisement request.

## Placement and lifecycle

One unit per eligible public page is the baseline. Public home, the services
directory, download page, supported service introductions, and explicitly public
school/project/contest discovery can host a slot. School content requires an
approved school's explicit advertising setting; empty, failed and mixed-policy
collections do not qualify.

Authentication, personal information, consoles, chat, editors, job execution,
private files, and unregistered hosts are excluded. Public-page eligibility is
independent of login: both settled signed-in and signed-out readers can receive
a unit. Loading authentication state does not initialize a unit. Existing first-party CBGPU app WebViews retain their registered web units on
eligible public web URLs. A genuine app bridge or CBGPU user agent admits the
non-sensitive `native=1` marker. This does not reuse a web ID in a native SDK.
The optional native SDK candidate is separate and off by default; it needs an
actual Android app unit and runtime validation. An explicit unavailable native
capability preserves the existing web fallback. A configured native surface is
exclusive, so a page never starts both advertising modes.

The initial SDK request waits until the slot intersects a visible document.
The script is asynchronous and receives no page referrer. The document takes
only one SDK lease, including duplicate component mounts, route changes and
viewport changes. There is no application refresh timer, iframe reload, hidden
request loop, click tracking, or blocker bypass.

The documented NO-AD callback and script-load errors hide the slot content while
retaining its reserved footprint. This avoids shifting nearby controls after a
late failure. No alternate advertising network or retry is silently introduced.
Navigation leaves the advertisement-bearing document before authentication or
private content is mounted. Removing a script alone cannot unload its globals.

## Console-controlled refresh experiment

[The official banner settings](https://kakaobusiness.gitbook.io/main/partner/adfit/start/ad-manage)
allow 30–120 seconds and recommend at least 60 seconds. Configure refresh in
**AdFit → Advertising management → Ad unit → Edit → Creative refresh**.
Do not add another timer in React. The inspected web documentation does not
specify background-tab/offscreen refresh semantics; do not infer those from
native SDK APIs.

Compare 60 and 120 seconds in separate recorded time windows. Record actual
console configuration, dates, report timezone, unit, device and deployment
version. A proposed interval is not an applied setting. Compare similar weekday
and traffic mixes, and retain inconclusive results when traffic is small.

## Reports and attribution

Import the actual [AdFit report download](https://kakaobusiness.gitbook.io/main/partner/adfit/start/report).
Do not use the Kakao Ad Exchange DSP API as an invented publisher revenue API.
Keep estimated earnings separate from finalized settlement data.

These two units are shared across placements. Their report totals support
banner-format comparison, not attribution to a particular page or physical
device. A narrow desktop container can legitimately use the 320px unit. Actual
physical-device revenue stays N/A without an official device dimension. Page placement
revenue remains N/A until independently reported units or a valid isolated
experiment provide attribution. Register additional real console units before
testing independently attributable placements; never manufacture unit IDs.

RPUV and revenue/session require matching period, timezone, device, scope and
real aggregate unique-visitor/session denominators. Do not sum daily uniques to
obtain monthly unique visitors. Pageviews, script requests, a visible slot or a
synthetic test impression are not AdFit impressions. Missing official counts,
denominators or viewability stay N/A rather than zero.

Report imports must not contain student names, email addresses, student numbers,
conversation contents or identifiers for individual revenue tracking. Do not
publish small-school revenue cohorts.

## Verification boundaries

`tests/ads/public-ad-browser.mts` uses real React, Chromium and a production Next
fixture, but intercepts every provider request with a synthetic SDK. It checks
desktop/mobile dimensions, horizontal overflow, duplicate mounts, auth and
school opt-outs, first-party app fallback, document navigation, resizing, no-fill,
blocked scripts and first-request offscreen deferral. It does not verify fill,
paid impressions, console settings, actual provider performance or earnings.

Measure production LCP, CLS and INP independently after a reviewed deployment.
Do not claim a revenue winner from synthetic fixtures or an unaligned report.
