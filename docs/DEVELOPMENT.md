# Local development

## Try the demo

Use Node.js 22.18 or newer and npm. No school account, Docker, database, GPU,
Firebase credentials or production environment file is required.

```bash
git clone https://github.com/CBGPU-Engineering/CBGPU-web.git
cd CBGPU-web
npm ci
npm run demo
```

Open **http://localhost:3100**, sign in with `student@example.invalid` or
`researcher@example.invalid`, password **`demo-only`**. These are synthetic local
accounts, not credentials accepted by the real website.

The demo uses the existing web UI and a loopback-only fixture API on port 54329.
The two ports must be free. The orange demo notice stays visible. The school clock
is fixed to November 3, 2026; application windows are open in the fixture.

Try signing in, opening the GPU reservation view, or opening self-study, connecting
the demo school identity, choosing a room/seat/teacher and applying or canceling.
Data lives only in memory and resets when the process restarts. Unsupported API
operations return 501, rather than forwarding to production.

Jupyter kernels, actual deployment builds, operator shells, email, push,
3D printing, laser cutting and Overleaf compilation are not started. The demo
is a contribution sandbox, not a replacement for integration tests or production
Supabase. Its known credentials and simulated responses must never be used as
production authentication. Demo builds reject non-loopback hostnames.

```bash
npm test
npm run build:demo
npm run start:demo
```

`build:demo` uses `.next-demo`, so it does not overwrite the normal production
build. The launcher injects placeholder-only environment values into child
processes; it never writes `.env.local`. It refuses checkouts containing real
`.env` files and does not inherit service credentials from the parent environment. Do not publish a demo build on a server.

The browser smoke test uses Playwright's Chromium installation:

```bash
npx playwright install chromium
# In another terminal, run npm run start:demo first.
node scripts/demo-smoke.mts
```

For the complete Docker demo use [CBGPU-platform](https://github.com/CBGPU-Engineering/CBGPU-platform),
then `docker compose -f compose.demo.yml up --build`.

## Work on a real integration

Use your own isolated backend. Copy `.env.example` to `.env.local`, configure
keys for that backend and start `npm run dev`. Do not point a local experiment
at the school's live database. Backend setup and migration notes are in
[CBGPU-backend](https://github.com/CBGPU-Engineering/CBGPU-backend). GPU, operator, mail, deployment and
LaTeX services require their own setup and verification.

The frontend includes host-dependent routing. Production configuration belongs to
[CBGPU-backend](https://github.com/CBGPU-Engineering/CBGPU-backend); see
[CONTRIBUTING.md](../CONTRIBUTING.md) for checks and the review process.


## TypeScript sources

All maintained browser, extension, demo, test and operator JavaScript has moved
to TypeScript (`.ts`, `.tsx`, `.mts` or `.cts`). Browser JavaScript and the
userscript are generated by `npm run build:browser`; do not edit the generated
files. Run `npm run check:source`, `npm run check:tooling`,
`npm run check:extensions`, `npm test` and `npm run build:demo`. The application
retains strict TypeScript checking; legacy tooling has a separate checked
configuration for dynamic test fixtures.

For an isolated local browser run, set `CBGPU_DEMO_PORT`,
`CBGPU_DEMO_API_PORT` and `CBGPU_DEMO_BUILD_DIR` (a `.next-...` directory)
consistently for the build and start commands, then set `DEMO_BASE` for browser
checks. Defaults remain port 3100, API port 54329 and `.next-demo`. The demo only
accepts loopback hosts and synthetic identities.


## Local site URLs

Run `npm run dev:sites` from this repository. The launcher runs one Next.js
process and maps local ports to the actual production Host headers. Application
routes, components and production domain checks are unchanged. Paths and queries
are preserved; the gateway also maps HTTP Location redirects between these sites.

| Production host | Local origin |
| --- | --- |
| cbgpu.com (student.cbgpu.com alias) | http://localhost:3000 |
| researcher.cbgpu.com | http://localhost:3001 |
| admin.cbgpu.com | http://localhost:3002 |
| app.cbgpu.com | http://localhost:3003 |
| docs.cbgpu.com | http://localhost:3004 |
| arxiv.cbgpu.com | http://localhost:3005 |
| manufacturing.cbgpu.com | http://localhost:3006 |
| print.cbgpu.com | http://localhost:3007 |
| laser.cbgpu.com | http://localhost:3008 |
| developers.cbgpu.com | http://localhost:3009 |

For example, `admin.cbgpu.com/admin/gpu` is `localhost:3002/admin/gpu`;
`docs.cbgpu.com/getting-started` is `localhost:3004/getting-started`.
There is no path-based override that turns the main site into the admin site.

The developer console is a separate Node service in CBGPU-backend, not a web
application route. Its local origin is http://localhost:3009; the gateway forwards it to the separate loopback service on port 3400. Use isolated developer-console settings for local work; do not connect local experiments to the production terminal or operator database.

The launcher binds only to loopback. Port 3099 is the private Next.js origin;
open the site ports above instead. Real integration credentials belong in the
ignored local environment file, never in this launcher or Git. The launcher supplies NEXT_PUBLIC_CBGPU_SITE_ORIGINS to the shared siteHref
resolver. Workspace and publication links resolve to local origins during
development. Production links remain canonical when the setting is absent or
NODE_ENV is production. The gateway maps server HTTP redirects as well.
